# dp3 결정 축 — Agent 격리 구조의 두 서브결정 (ATAM 보조 자료)

> category: DP-criteria | for: dp3(Agent 격리 구조 — DP id 확정 전) | updated: 2026-07-31
> 목적: 팀 초기 프레임 **"(1) container냐 VM이냐 (2) HITL 강제냐 자동 승인이냐"** 를 재정식화한다. 두 축은 dp4의 2x2(같은 결정의 두 손잡이)와 달리 **서로 다른 실패 모드를 막는 독립 서브결정**이며, 교환점(TP) 하나로 연결된다.
> 관련: R-01(축① 스펙트럼) · R-02(축② 레퍼런스) · dp2(일회용 컨테이너 실행구조) · C-03 · QA-03 · DP-01 · DP-0003

## 왜 재정식화가 필요했나 — 원 프레임의 문제 3개

1. **축(2)가 SSoT와 자기모순**: "전면 자동 승인"은 C-03의 pass/fail 게이트(`고위험 액션 HITL 통과율 100%·우회 0건`)를 정면 위반 → **부적격(inadmissible), 비교 매트릭스에 올라올 자격 없음**. "전면 HITL"은 시스템 전제("사람 개입 없이")·QA-01(ASR#1, 사람 승인자 = 공유 유한자원 = USL α항)·rubber-stamping(승인 피로) 위험에 걸림. **양 끝이 모두 격추된 이지선다**였다.
2. **축(1)이 지배적 중간 지대를 가림**: container↔VM 사이의 gVisor(유저스페이스 커널)·microVM(Kata/Firecracker)이 실무 정석인데 이지선다에서 지워짐 (상세 R-01).
3. **범주 혼동**: 두 축은 서로 다른 실패 모드를 막는다 — 하나의 2x2로 묶으면 안 됨 (아래 §축 간 관계).

## 축① — 실행 격리 경계 등급 (boundary class)

손잡이: **경계 강도 ↔ 기동시간·밀도 비용**. 상세 스펙트럼·비교표·근거는 `R-01` 참조.

```
runc(기준선·약)  →  gVisor  →  microVM(Kata/FC)  →  full VM(기준선·과잉)
                    └── 결선 후보 ──┘
```

- 양끝 기준선 격하(dp4 무브): runc는 위협 모델(C-03 injection 잔여 ~30%의 임의 코드 실행) 미달, full VM은 microVM에 지배(같은 벽을 더 비싸게).
- **가르는 질문(실측 의존)**: Q1 인프라(bare-metal/nested virt 지원 — 미지원이면 microVM 탈락) · Q2 성능(dp2 20GB 로컬 I/O에서 gVisor 가로채기 세금이 QA-10 ≤5% budget 잠식 여부).

## 축② — 승인 경계 배치 (approval boundary placement)

결정은 "HITL이냐 아니냐"가 아니라 **"어떤 액션 경로에 어떤 승인 메커니즘을 배정하는가"**다. 메커니즘은 3단이다 (근거·레퍼런스는 `R-02`):

| 메커니즘 | 사람 개입 시점 | 본 시스템 대응(예) |
|---|---|---|
| 자동 (샌드박스 내부) | 없음 | 파이프라인 노드 실행 · 중간 산출물 처리 |
| **정책 사전승인 (standing)** | 설정 시 1회 | 내부 레지스트리 배포 · 허용된 외부 API |
| 액션별 HITL | 런타임 매번 | production 배포 승격 · credential 사용 · delete |

- **배치 원리 — 승인 경계 = 격리 경계**: 액션의 효과가 샌드박스 폐기와 함께 사라지면(가역) 자동, 샌드박스를 넘어 지속되면(비가역·외부 노출) 게이트. "효과가 컨테이너 폐기 후에도 남는가"는 **기계 판정 가능한 구조적 술어**라, 사람이 유지보수하는 액션 목록보다 우회 논쟁 표면이 작다. C-03의 "우회 = 0건" 논증도 액션 단위가 아닌 **경계 통과 인터페이스 단위**(레포 push · 배포 API · credential/secret 접근 · 아티팩트 발행 · 프록시 allowlist 밖 egress)로 수행한다.
- **기준선 격하**: 전면 HITL(사람=α항·rubber-stamping)·전면 자동(C-03 위반 부적격)은 비교 기준선으로만 유지.
- **가르는 질문(실측 의존)**: 예상 고위험 액션 발생률 × 승인 SLA가 **사람 승인 처리량과 E2E budget(QA-10) 안에 드는가**. ≥50모델/일 throughput 게이트(QA-01) 하에서 배포 경계를 전부 액션별 HITL로 두면 하루 ~50건 승인 → rubber-stamping 임계 검토 필요 → canary/내부 배포는 정책 사전승인 + production 승격만 HITL 같은 배정이 결선 후보.

## 축 간 관계 — 도출이 아니라 전제 공급

두 축은 서로 다른 실패 모드를 막는다:

- **축①(샌드박스)** = *비인가 능력* 차단 — 탈출·측면 이동·권한 밖 자원 접근.
- **축②(승인)** = *인가됐지만 잘못된 판단* 차단 — injection에 조종당해 정상 권한으로 하는 나쁜 배포. **샌드박스가 아무리 강해도 인가된 액션 자체는 못 막는다.**

권한 경계를 세 질문으로 쪼개면 축①이 정하는 것은 하나뿐이다:

| 질문 | 무엇이 정하나 |
|---|---|
| ⓐ 경계가 **어디** 있나 (통과 지점 목록) | **토폴로지** — dp2의 일회용 컨테이너 구조 + 시스템 외부 인터페이스. 축①과 무관하게 고정 |
| ⓑ 경계 **안쪽**을 무승인으로 둘 수 있나 | **← 축①이 정함.** 격리 등급이 위협 모델을 담아내면 "내부 = 자동 승인" 성립 |
| ⓒ 경계 **통과 지점별** 메커니즘 배정 | **축②의 독립 결정** — 축① 등급과 무관하게 남는 질문 |

- **TP-1 (격리 강도 ↔ 자동존 폭)**: 축①이 충분하면 축②의 자동존이 넓어지고, 불충분하면 내부에도 게이트가 필요해져 자동존이 좁아진다. 부분 대체 관계(완전 대체 아님 — 위 실패 모드 분리 때문).
- ⚠️ 축①→축② **자동 도출로 서술 금지**: 도출로 묶으면 ⓒ의 실제 결정(사전승인 vs HITL 배정, rubber-stamping 임계)이 증발하고, C-03의 HITL 100% 게이트가 격리 등급과 무관하게 상시 유효하다는 사실이 가려진다.

## 기존 DP와의 소유권 정합 (중복 결정 방지)

C-03 검증 전략이 이미 **DP-01 1안(HITL gate)·DP-0003 1안(사전 권한 게이트·admission)** 에 게이트 책임을 귀속시켰다. 따라서:

- **dp3 축②의 스코프 = 승인 경계의 *배치·입도*** (어느 통과 지점을 어느 메커니즘에 배정하는가). **게이트의 존재 자체를 재결정하지 않는다** — 존재는 DP-01/DP-0003/C-03 참조.
- dp3 본문 작성 시 DP-01·DP-0003과의 관계(계층/참조)를 명시해 이중 소유권(F-03류 이중 제어평면과 동형의 안티패턴)을 차단할 것. → open-issues 등재 후보.

## 결정에의 함의 (본문 작성 가이드)

- 결선: **축① gVisor vs microVM** (Q1·Q2 실측) × **축② 통과 지점별 배정표** (발생률·SLA 실측). 두 축 모두 "구조는 고정, 수치는 측정으로" 문형.
- ATAM 요소 후보: SP(샌드박스 기동 → QA-10/QA-09 · 에스컬레이션율 → QA-01 사람-α) / TP-1(위) / Risk(rubber-stamping, nested virt 미지원, gVisor 대용량 I/O 세금, microVM 밀도 비용) / Non-Risk(Kata RuntimeClass로 C-01 충족).
- ⚠️ 범주 오류 재발 방지(F-08): microVM ≠ microkernel. 축① 어휘는 Bulkhead/Sandbox/Defense-in-depth 계열.
