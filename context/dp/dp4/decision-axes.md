# DP-0004 결정 축 — 실행구조 대안 분류 렌즈 (ATAM 보조 자료)

> category: DP-criteria | for: DP-0004 | updated: 2026-06-22
> 목적: DP-0004 실행구조 대안(1안·2안·A5·A8)을 정렬하는 **2개 직교 축**을 정의한다.
> 이 문서는 *분류 기준(criteria)* 이고, 축별 점수·수렴은 `evaluation.md`가 담당한다 (점수와 기준 분리 = ATAM 정석).
> 관련: 1안/2안(DP-0004 본문) · A3~A7(approaches/) · A8(approaches/, 발굴 예정)

## 왜 이 렌즈가 필요한가
기존 evaluation.md는 신규 대안을 발굴하며 "4개 직교 축(실행위치/분배/분해/변종·복구)"을 제시했다. 그러나 **DP-0004의 본질적 결정**(노드 작업을 어떤 실행 구조로 처리할지 = "실행위치/자원 모델" 축) 안에서 1안·2안·A5·A8이 **어떻게 서로 관계 맺는지**가 흐릿했다. 이 문서는 그 축을 **2개의 더 근본적인 손잡이**로 분해해, 4개 대안을 하나의 2x2 좌표에 고정한다. proper ATAM의 architectural-approach 분류 기준으로 사용한다.

## 두 직교 손잡이

- **축 ① 자원 수명 (lifecycle)**: 노드 작업을 처리하는 컴퓨트를 어떻게 점유하는가.
  - **상주 풀(standing)**: 서버/인스턴스를 미리 띄워 유지. cold-start 없음, 유휴 시 자원 낭비.
  - **일회용(ephemeral, scale-to-zero)**: 호출마다 컨테이너를 띄워 1건 처리 후 종료. 유휴 0, 단 cold-start.

- **축 ② 데이터-컴퓨트 배치 (placement)**: 20GB+ 중간 산출물을 어떻게 전달하는가.
  - **데이터를 컴퓨트로 (원격)**: 오브젝트 스토리지(claim-check)로 전달. 컴퓨트 배치 자유, 단 **전달세금**(QA-08 오버헤드) 발생.
  - **컴퓨트를 데이터로 (로컬)**: 데이터가 있는 노드에 작업을 핀(data-affinity)으로 박아 로컬 디스크/스트리밍 전달. 전달세금 회피, 단 로컬 디스크는 내구성 약함.

## 2x2 매핑

| | **데이터를 컴퓨트로** (원격, 전달세금↑) | **컴퓨트를 데이터로** (로컬, 전달세금↓) |
|---|---|---|
| **상주 풀** | **1안** 타입별 공유 서버 풀 + 오브젝트 스토리지 | **2안** co-located 상주 인스턴스 + 로컬 디스크 |
| **일회용** | **A5** ephemeral, 클러스터 어디든 배치 | **A8** ephemeral + 데이터 있는 노드에 핀 (신규) |

> A8은 그동안 비어 있던 칸이다. "A5의 일회용 컨테이너 모델 + 2안의 로컬 전달(노드 핀)"으로 도출했다 (`approaches/A8-*` 정식 발굴 예정).

## 계열·스펙트럼 통찰

- **세로 형제 (수명만 다름)**: 1안↔A5(원격 계열), 2안↔A8(로컬 계열). 각 계열에서 일회용(A5/A8)은 상주(1안/2안)의 **유휴 낭비·격리 약점을 고친 진화형**이다. → 1안은 A5에, 2안은 A8에 지배되어 후보 격하 가능.
- **가로축 = 전달세금 계열**: 1안·A5·(A3)는 전달세금을 내고, 2안·A8은 회피한다. 이 가로축이 QA-08의 핵심 교환점.
- **A5↔A8은 양 끝, 규모에 따라 수렴**: 규모가 작아 한 노드에 모델 파이프라인이 들어가면 A8이 전달세금 0으로 우위. 모델이 폭증해 노드를 넘나들면 로컬리티가 어차피 깨져 A8도 원격 전달로 degrade → A5에 수렴. (A8 = locality-first, 넘치면 spill)

## 부수 trade-off (로컬 vs 원격 계열의 숨은 비용)
- **로컬 계열(2안·A8)**: 전달 빠름, 그러나 로컬 디스크는 노드 사망 시 산출물 유실 → 복구 불리.
- **원격 계열(1안·A5)**: 전달세금 있으나 오브젝트 스토리지는 노드 사망에도 산출물 보존 → 복구 유리.
- 즉 가로축은 **Performance(전달) ↔ Reliability(복구)** 교환을 내포. (점수화는 evaluation.md)

## 결정에의 함의
- **최종 대결은 A5 vs A8** (각 계열 진화형). 1안·2안은 비교 기준선·지배당하는 후보로 격하.
- **가로축을 가르는 단일 질문**: `(4단계 × 20GB 왕복) ÷ 스토리지 대역폭`이 E2E의 5% budget(QA-08) 안에 드는가.
  - 들면 → 전달세금 감내 가능 → A5(단순·복구 유리).
  - 넘으면 → 전달세금 회피 필요 → A8(로컬, locality-first).
- 이 산식은 팀 검증 대상(실측·노드 사양 의존). 본 문서는 **결정의 구조**를 고정하고, 수치는 evaluation.md/팀 협의로 채운다.

## 적용 메모
- A4(구조 분해)·A6(내구 실행)·A7(변종)은 이 2x2와 **직교한 보강축**으로, 어느 칸 위에도 얹을 수 있다(예: A8 + A4 로컬 스트리밍, A5 + A6 내구 복구).
- A3(비동기 큐)는 분배축이나 전달 면에서 원격 계열(전달세금)에 속한다.
