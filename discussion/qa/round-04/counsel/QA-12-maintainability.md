## Reviewer 지적 요약
CIS p95 재배치 불요(건강)+경계 정의 조건 정확. 잔여(Low): (1) **CIS p95가 정수 1/2/3이라 변별 거침 + 보간 p95(비정수) 미상정 + 동률 변별 불가**(권고 2), (2) **별점 축(CIS)과 정의가 강조한 지배 비용(prompt/모델 교체)이 어긋남** — agentic 축이 보조 게이트로 밀림(권고 1·C3), (3) ★ 급간이 컴포넌트 경계 굵기 선택의 함수(권고 3).

## 개선안 (정의·KPI 기존→제안)
### (A) 정수 입도 구간화 (권고 2)
- ★ 급간 기존: `★★★ ≤1 / ★★☆ =2 / ★☆☆ =3`(단일 정수, p95=2.4 미상정). → 제안: **`★★★ p95≤1 / ★★☆ 1<p95≤2 / ★☆☆ 2<p95≤3 / 불합격 p95>3`**으로 구간화 — 분수 p95(백분위 보간) 수용 + 동률 변별 보강(p95=2.4는 ★☆☆).
### (B) agentic 축 보조 별점 축 (권고 1·C3)
- **기존**: CIS가 유일 main 별점 축인데 정의 지배 비용(prompt/tool-def·모델 교체)은 보조 게이트로 밀림. → 제안: **prompt/tool-def 수정 수를 보조 별점 축 병기**(CIS와 이중 축). 보조 ★: `prompt/tool 수정 ≤1 = ★★★ / =2 = ★★☆ / =3 = ★☆☆`. ATAM 비교 시 CIS 동률이면 agentic 축으로 변별(정의↔별점 축 정합 복구).
### (C) 경계 종속 silent cap (권고 3)
- `★ 급간은 컴포넌트 경계 굵기 선택의 함수 — 경계 굵게 잡으면 CIS↓(★↑), 잘게 잡으면 CIS↑(★↓). 경계 정의 조건으로 고정하나 본질적 종속 명시`.

## 근거 (레퍼런스 + 검증 결과)
**C4 — 모델 마이그레이션 비용**: 모델 교체 비용(2 eng × 2주 ≈ $16k, VentureBeat)은 본 검증에서 1차 대조 미완 → "확인 불가, 무중단·온보딩 ≤1일 보조 게이트 정당화용". workflow-as-code(activity 교체·큐/계약 분리)·blue-green은 결합도 낮추는 표준 메커니즘. CIS(컴포넌트 영향 범위)는 전통 SW 결합도 지표 — agentic 지배 비용과 보완 관계.

## PoC 증명법
### PoC-12: CIS p95 + agentic 수정 수 이중 축 (변경 시나리오 분석 아키타입)
- 가설: "CIS p95와 prompt/tool 수정 수가 변경 시나리오 세트로 측정되고 경계 정의 sensitivity가 노출된다."
- 지표: 변경 시나리오별 CIS 분포(p95/max), prompt/tool 수정 수, 경계 굵기 ±1 시 CIS 변동. 합격선: 경계 정의 고정 하 ★ 변별 + 동률 시 agentic 축 변별.
- 셋업: 변경 시나리오 세트(노드 교체·SDK 플래그·모델 v→v+1·온보딩), mock 결합도 그래프.
- 절차: ① 시나리오별 CIS 집계. ② prompt/tool 수정 수 집계. ③ 경계 굵기 ±1 민감도.
- 합격 기준: 두 축이 ATAM 변별 제공 + 경계 종속성 정량 노출.
- 규모/기간: 시나리오 4종, ~0.3일.
- 리스크/한계(silent cap): mock 결합도가 실시스템보다 낮으면 CIS 낙관 편향.
