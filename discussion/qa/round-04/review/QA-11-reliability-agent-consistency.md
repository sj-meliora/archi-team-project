# Review: QA-11 Reliability — Agent 결과 일관성

> source: context/qa/QA-11-reliability-agent-consistency.md + QAS-11-reliability-agent-consistency.md
> verdict: **Sound ◎ / KPI ○** — pass^k 전면 재배치(70%→25/40/60)는 방향·근거 모두 정당하나 **τ-bench pass^k의 apples-to-apples(k=4/8 → k=5 보간·도메인 불일치)와 ★★★ 60% 도달 가정의 낙관**이 잔여 · severity **Med**
> lenses: (1) Agentic Workflow 전문가 · (2) 20년차 수석 아키텍트 · (3) 대규모 Workflow Runner 인프라 아키텍트
> 특별 초점(round-04): ★ 등급 척도(pass^k 70%→25/40/60% 전면 재배치) 검증을 가장 두껍게.

## 원문 요약
- **정의**: 동일/유사 입력에서 **유효(정책 허용) 결정의 안정성**. 일관성 ≠ 정확성(QA-07 짝). 캐시는 일관성 입증 못 함(치트).
- **헤드라인 KPI**: `캐시 On/Off 일관성 갭 Δ` 대조 시연(명제형·Constraint 성격 → 시연 게이트, 불변).
- **★ 급간(main = 순수 추론 pass^5, 캐시 우회)**: ★★★ ≥60% / ★★☆ 40~60% / ★☆☆ 25~40% / 불합격 <25% 또는 Δ시연 실패·H_norm>0.2·②-1<95%. §측정 보정 `≥70% → 25/40/60%`.
- **동반 게이트**: k=5 고정 · 캐시 우회 · `H_norm ≤0.2 AND ②-1 ≥95%`. ②-2(정밀 유효-결정률)는 QA-07 golden 의존 → open-issue(OI-7) 제외.

## 렌즈 1 — Agentic Workflow 전문가 관점 (★ 경계의 필드 벤치마크 근거 보강/반박)

### 1-1. τ-bench 인용이 **같은 것을 재는가** — k 보간과 도메인 불일치 (apples-to-apples)
★ 경계 전부가 τ-bench 숫자에서 나온다: frontier retail pass^1 ~80%, GPT-4o pass^1 61% → pass^4 ~37% → pass^8 ~25%. **red-team 반박 4건**:

1. **pass^5는 τ-bench에 직접 없다 — 보간값이다.** τ-bench 표준 보고는 pass^1·pass^4·pass^8(또는 pass^k 곡선)이다. 우리가 쓰는 k=5는 GPT-4o의 관측점 pass^4(~37%)와 pass^8(~25%) **사이를 보간**한 것이다. pass^k는 k에 대해 **단조 급감**(독립 시행 가정 시 대략 기하급수)하므로, GPT-4o pass^5는 ~37%보다 낮은 ~33% 부근으로 추정된다. 그런데 ★☆☆ 하한을 **25%(=pass^8값)**에 두었다 — **k=8 값을 k=5 합격선에 쓴 것**은 약간 관대한 쪽으로 어긋난 보간이다(같은 k에서 비교하면 GPT-4o pass^5 ≈33% > 25% 하한이라, 하한은 GPT-4o조차 여유 통과). 경계 자체의 단조성은 깨지지 않으나 **"필드 바닥"의 정의가 k를 섞어 잡혔다.** → 명시 필요.

2. **도메인 불일치** — τ-bench는 retail·airline **고객 응대 멀티턴 도구사용** 벤치마크다. 우리 시스템은 **SDK 빌드 파이프라인(IR→Optimizer→Quantizer→Compiler) 자동화**다. "유효 결정"의 의미가 다르다(고객 의도 충족 vs 빌드 config 결정의 안정성). pass^k의 *난이도 프로파일*이 다를 수 있어 **τ-bench 대역을 그대로 빌려온 것이 우리 task에서 ★ 경계로 타당한지 보증이 없다.** (QA-06과 동형의 apples-to-apples 약점.)

3. **단일 벤치마크 과의존** — τ-bench(Sierra/arXiv 2406.12045) + Alan 블로그(해설). 사실상 τ-bench 한 출처 계열이다. self-consistency voting·temp=0이 pass^k를 얼마나 올리는지의 **독립 근거가 없어**, ★★★ "60%대 pass^5는 frontier + voting 가정 최상위"가 **희망적 추정**에 머문다.

4. **인용 정확성 확인 불가(웹 도구 없음)** — pass^1 80%/61%, pass^4 37%, pass^8 25%는 본 환경에서 원문 대조 불가. Council이 round-05에서 1차 출처(arXiv 2406.12045 표·Sierra 블로그)로 재확인하고, **pass^5 직접 보고치가 있으면 보간 대신 사용**할 것.

### 1-2. agentic 고유 강점 — 헤드라인 Δ 대조는 옳다
"캐시 On은 ~100%로 자명히 부풀어 측정 오염" → 캐시 우회 순수 추론 모드 측정은 **memoization 치트를 정확히 자각**한 agentic 통찰. 헤드라인을 절대값이 아니라 Δ 대조(우리 조건에서 실제 시연 가능)로 둔 것은 round-01 contention의 정당한 산물 — 유지. ◎.

## 렌즈 2 — 20년차 수석 아키텍트 관점 (QA 완성도 · ★ 급간 검증 핵심)

### 2-1. Sound / 게이트 분해의 타당성 (규칙 5) — **진짜 gradable proxy인가, 가짜 급간 날조 아닌가**
**규칙5가 가장 빛나는 케이스이자 가장 위험했던 케이스다.** 헤드라인 Δ는 대조/명제형(0건 절대형) → 별점 무의미 → 시연 게이트로 빼고, **gradable한 pass^5**에만 별점을 매겼다. Seat 3가 "보조지표 전원 미실측 시 Constraint flag"를 우려했고, **②-1·H_norm이 우리 조건에서 산출 가능한 gradable proxy라 QA로 성립**시킨 판단(97행)은 방법론 규칙5를 정확히 통과한다. **가짜 급간 날조 아님.**

**그러나 red-team 반박 1건(가장 날카로움)**: main 급간 축인 **pass^5 절대값은 우리 조건에서 실측 불가([발표 서사])**다(검증 전략 72행: "절대값 실측은 실제 에이전트 필요 — 미실행"). 즉 **별점을 매기는 main 축이 정작 우리가 못 재는 값**이다. 캘리브레이션 노트도 silent cap ①로 이를 자인한다("pass^5 *절대값*은 미실측 — main 축은 '이렇게 등급화한다'는 형식 제시"). → **QA-06과 비대칭**: QA-06의 별점 축(차단율)은 [생략]됐어도 *원리상* 우리가 잴 수 있는 값인데, QA-11의 별점 축(pass^5)은 [발표 서사]라 **PoC로도 못 채운다.** 이 경우 ★ 급간은 "ATAM 두 설계 비교"에서 **실측 별점이 아니라 모델 추정 별점**으로만 쓰일 수 있다. 정직하게 명시돼 있어 결함은 아니나(silent cap), **★ 급간의 실효성이 QA-06보다 약하다** — Med 사유.

→ 진짜 우리 조건에서 산출 가능한 gradable proxy는 **②-1(룰 게이트 통과율)·H_norm**인데, 이 둘은 별점 축이 아니라 **동반 게이트(pass/fail)**로만 쓰인다. **차라리 산출 가능한 ②-1/H_norm 중 하나를 main 별점 축 후보로 검토**할 가치가 있다(아래 권고).

### 2-2. ★ 경계가 reasonable한가 — 등간격 아닌, 곡선 인식한 배치
경계: ★☆☆ [25,40) · ★★☆ [40,60) · ★★★ [60,∞). 폭이 15·20·∞로 **비등간격**이고, 이는 pass^k 곡선의 급감을 의식한 배치로 보인다(높은 구간일수록 도달이 어려우니 ★★★ 폭을 열어둠). **QA-06보다 분포 인식이 낫다.** 다만:
- **25 하한 = GPT-4o pass^8**(k 불일치, 렌즈1-1) — k=5 기준이면 약간 낮게 잡힌 바닥.
- **40 경계 = GPT-4o pass^4(~37%) "바로 위"** → 근거 명확.
- **60 경계 = frontier pass^1 80% → pass^5 상한 대역 + voting 가정** → **가장 약한 경계.** frontier pass^1 80%에서 pass^5로 내려오면(독립 시행 가정 0.8^5≈0.33) 60%는 **frontier에서도 voting·상관성 가정 없이는 도달 불가**다. 즉 ★★★ 60%는 "이론 천장에 margin"이 아니라 **이론 천장을 넘는 낙관**일 수 있다(0.8^5=33%인데 60%를 요구). 표는 "structured output/self-consistency voting 가정 최상위"로 정당화하나, **voting이 pass^5를 33%→60%로 끌어올린다는 근거가 인용에 없다.** → ★★★가 **사문화(아무도 못 받음)** 위험. 이건 round-04 특별 초점의 "★★★ 사문화" 정확한 후보다.

### 2-3. 하한 보정의 정합성 (OI-9 후속) — 정합 통과, 변별력 양호하나 ★★★ 도달성 의심
- **상→신 정합**: §측정 42행(`25/40/60%`), ## 등급 척도 표, 변경 이력, round-03 counsel(70→25/40/60), QAS-11 Measure(12·16행 `≥25/40/60%`) — **5곳 일치**. glossary 수치 없음 → 충돌 없음. **OI-9 통과.**
- **변별력**: 구 70% 하한은 frontier pass^5도 못 넘어 ★ 전체가 죽은 등급 → 보정 사유 정확. 신 25% 하한은 GPT-4o pass^8(필드 바닥) 수준 → ★☆☆ 비사문화. **단 ★★★ 60%는 도달 불가 의심**(2-2) → 보정이 ★☆☆은 살렸으나 ★★★를 다시 사문화 위험에 둘 수 있다. **물러진 게 아니라 윗쪽이 너무 빡빡**한 반대 방향 문제. → Med.
- **하한 보정 ↔ KPI 정의 정합 재확인**: 캘리브레이션 노트가 "KPI 정의 `pass^k 70%`는 도메인 쉬운 단일 task 가정이었음"을 OI-7 등록 대상으로 명시 → **정합 재확인이 트래킹됨**(통과). 다만 §측정 본문(40행)은 여전히 "합격 하한 ≥25%"로 갱신됐으나 캐시노트 50행 "pass^k 70%" 예시문이 **구값 잔존**(50행 `pass^k 70%·②-1 95%·H_norm 0.2`) → **본문 내 구값 흔적 1건**(아래 권고 3).

### 2-4. Measurable / Consistent
②-2를 placeholder가 아니라 **선언된 open-issue(OI-7)**로 강등한 것은 정직(46행). H_norm 정규화 엔트로피 정의 명확. 정의↔KPI↔QAS-11 일치. ○ — 단 §측정 50행 구값 잔존이 미세 흠.

## 렌즈 3 — 대규모 Workflow Runner 인프라 아키텍트 관점

★ 급간(pass^5)을 runner에서:
- **pass^5 측정 = 동일 입력 k=5 반복 fan-out**: control plane이 같은 task를 5 worker에 복제, **캐시 우회 모드 강제**(memoization 무력화 플래그). worker는 model/prompt/tool/seed 핀닝 — 단 LLM 비결정은 seed로도 완전 제거 안 되므로 pass^k의 분산이 곧 측정 대상. durable execution으로 5회 trace를 replay 가능하게.
- **②-1 룰 게이트·H_norm = 같은 5 결과를 라벨 매핑 컴포넌트에 통과** → ②-1(hard-invalid 차단율)·H_norm 산출. **이 컴포넌트는 우리 조건에서 실제 구동 가능**(렌즈2가 지적한, 진짜 gradable한 부분).
- **표본**: pass^5의 ★★☆/★★★ 경계(40/60)를 신뢰하려면 task 다수에 대한 pass^5 분포가 필요 → N개 task × 5회 = 5N 호출. 외부 LLM rate-limit(QA-01·QA-08 천장)·토큰 경제와 trade-off → token-bucket·backlog 오토스케일로 batched 실행.

**runner 측 KPI 제안**:
- `pass^5 추정 표준오차 ≤ (경계 간격/2)` — N task가 작으면 40 vs 60 변별 불가(silent cap).
- `캐시 우회 검증: pass^5(On)−pass^5(우회) = Δ > 0이 N task에서 일관` (헤드라인 Δ를 runner가 자동 산출 — 이게 우리 조건에서 진짜 시연 가능한 부분).
- `②-1 룰 게이트 throughput` — 라벨 매핑 컴포넌트가 ②-1·H_norm·QA-06 차단율 라벨링과 **공유 자산**(co-location).

## Stage 2 권고

1. **[★★★ 도달성 재검토 · Med — 가장 중요]** ★★★ pass^5 ≥60%는 frontier pass^1 80% → 독립시행 0.8^5≈33%로, **voting이 33→60%를 끌어올린다는 근거가 없으면 사문화**. `기존: ≥60%(frontier+voting 가정 최상위)` → `제안: (a) self-consistency voting의 pass^k 향상 폭을 1차 출처로 보강하거나, (b) ★★★를 ≥45~50%로 하향(0.8^5 부근 + voting 소폭)`. Council round-05가 voting 근거를 못 대면 (b).
2. **[k 보간 명시 · Med]** ★☆☆ 25% 하한이 GPT-4o **pass^8** 값이고 main 축은 **pass^5**임을 노트에 명시. `제안: pass^5 직접 보고치가 있으면 사용; 없으면 "25%는 pass^8 바닥의 보수적 차용(k=5 환산 시 GPT-4o≈33%라 하한은 여유)"으로 보간 출처 명기`.
3. **[구값 잔존 정리 · Low]** §측정 50행 캐시노트 `위 수치(Δ 대조·pass^k 70%·②-1 95%·H_norm 0.2)` 중 **`pass^k 70%`가 보정 전 구값** — `pass^5 25/40/60%`로 정정(보정 후 표와 불일치하는 본문 내 마지막 잔존).
4. **[main 축 후보 재검토 · Med]** pass^5가 [발표 서사]라 실측 불가인데 별점 축이다. `검토: 우리 조건에서 실제 산출 가능한 ②-1(룰 게이트 통과율)·H_norm 중 하나를 보조 별점 축으로 병기`해 ATAM 두 설계 비교 시 **모델 추정(pass^5) + 실측 가능(②-1/H_norm) 이중 축**으로 변별력 보강. (현재 ②-1·H_norm은 pass/fail 게이트로만 소비.)
5. **[apples-to-apples 명문화 · Med]** τ-bench는 retail/airline 고객응대 도메인이고 우리는 SDK 빌드 파이프라인임을 silent cap 추가 — "대역 차용은 난이도 프로파일 차이 가정"임을 명시.
6. **[표본 크기 silent cap · Low]** ## 검증 전략에 `pass^5 ★★☆/★★★ 경계(40/60) 변별엔 N task × 5회 분포 필요 — N 작으면 표준오차가 경계 간격 초과` 명시.
7. **DP·교차 의존**: ②-2 ↔ QA-07 golden(OI-7) 미닫힘 유지(이번 라운드 범위 밖, 정상 트래킹). DP-0005(공유 캐시)가 **캐시 우회 모드**를 명시 제공하는지 DP 역검토(★ main 축 측정의 전제).
