# Review: QA-13 Cost-economy — 완료 모델당 비용

> source: context/qa/QA-13-cost-economy.md + QAS-13-cost-economy.md
> verdict: **Sound ◎ / KPI ○** — 절감률 70→50% 재배치(규칙2 핵심 케이스) + $/모델 게이트 분리는 정확. 잔여는 ★ 전 경계가 baseline 추정([발표 서사])에 좌우 + ★★★ 75% 단일 사례(법무) 의존 · severity **Med**
> lenses: (1) Agentic Workflow 전문가 · (2) 20년차 수석 아키텍트 · (3) 대규모 Workflow Runner 인프라 아키텍트
> 특별 초점(round-04): ★ 등급 척도(절감률 70→50%, $/모델 게이트화) 검증 무게중심.

## 원문 요약
- 정의: 모델 1건 완료 총비용(토큰+compute+재시도)을 수작업 대비 절감. ROI top-line.
- 헤드라인 KPI: `완료 모델당 비용 $ ≤$5`(보정으로 게이트화) + `절감률 ≥50%`(★ 급간 축).
- ★ 급간: main = 수작업 대비 절감률(정방향). ★★★ ≥75% / ★★☆ 60~75% / ★☆☆ 50~60% / 불합격 <50% 또는 $/모델>$5. 조건: 동일 baseline·단가표·캐시 On.

## 렌즈 1 — Agentic Workflow 전문가 관점 (필드 근거 보강/반박)
"top-line은 요청당 토큰이 아니라 완료 모델당 비용"(요청 수·재시도 폭발 시 모델당 비용↑)을 정확히 짚고, 재시도 오버헤드를 분리 집계한 것은 agentic 비용 통찰. caching(cache read ≈ base 10%, 7x↓)이 토큰축을 끌어내린다는 근거도 정합. 그러나 red-team 반박: **★★★ 75%가 "법무 75% 사례" 단일 데이터포인트**에 의존(Medium 블로그). 법무 멀티에이전트 절감과 **SDK 빌드 파이프라인 절감**은 도메인이 완전히 다르다(apples-to-apples 약함). 또 절감률은 **수작업 baseline 인건비·시간 가정**에 좌우되는데 그게 [발표 서사](추정값) → ★ 전 경계가 추정 baseline의 함수다. → round-05 Council이 도메인 무관 자동화 절감 분포 보강.

## 렌즈 2 — 20년차 수석 아키텍트 관점 (★ 급간 검증 핵심)
- **규칙2·4 적용 모범**: $/모델(인프라 단가 의존)을 게이트로 빼고, gradable·단가 비의존인 절감률을 main 별점 축으로(규칙4). 절감률 70→50% 재배치는 "자동화 절감 필드 30~75%에서 70% 하한은 ★★★ 사문화"를 정확히 교정(규칙2). round-04 특별 초점 "비현실 하한 군집"의 핵심 사례. ◎.
- **급간 reasonableness**: ★☆☆ 50~60 · ★★☆ 60~75 · ★★★ ≥75. **비등간격(10/15/∞)** — 자동화 절감 분포(30~75%, 대부분 30~50%대)를 반영해 상단을 넓힘. 단 ★★☆ 폭(15%p)이 ★☆☆(10%p)보다 넓은 근거가 표에 약함(margin 자의성 C2).
- **하한 보정 정합(OI-9)**: §측정(46~48행 ≥50%, 70%=★★☆), 등급표, 변경이력, counsel(70→50%), QAS-13(`≥50% ★☆☆; 70%=★★☆`) **일치**. glossary 없음. **OI-9 통과.** 단 변경이력 138행이 "open-issues.md와 정합 점검(본 작업 범위 외)" — OI 등록이 아직 미완일 수 있음(권고 4).
- **변별력**: 구 70% 하한은 필드 상단이라 ★★★ 사문화(보정 사유 정확). 신 50%는 "Forrester ~30% 위 + ROI 설득 진입선"이라 ★☆☆ 비사문화. ★★★ 75%도 상위 사례 대역이라 비사문화. 양호. ○.

## 렌즈 3 — 대규모 Workflow Runner 인프라 아키텍트 관점
절감률 = ($/모델 vs 수작업 baseline). $/모델 = 토큰비 + compute(scale-to-zero로 과프로비저닝 0) + 재시도. caching A/B(QA-05 공유) 위에 compute 단가·baseline 얹어 산출. **재시도 오버헤드 분리**가 핵심 — 재시도가 비용 잠식하므로. runner KPI: `$/모델을 토큰/compute/재시도 3축 분해 + 재시도율이 절감률에 미치는 민감도` — 재시도 폭증 시 절감률 붕괴를 ★가 잡는지.

## Stage 2 권고
1. **[baseline 추정 silent cap · Med]** ★ 전 경계가 수작업 baseline 인건비·시간 가정([발표 서사])의 함수임을 ## 등급 척도에 명시 — 절감률 절대값은 baseline 정의에 좌우(C3 군집: main 축이 추정 의존).
2. **[★★★ 75% 다양화 → Council · Med]** 법무 단일 사례 대신 도메인 무관 자동화 절감 분포(30~75%)에서 ★★★ 위치 재확인. round-05 Council이 1차 출처(Forrester·Requesty·법무 블로그) 실재·인용 정확성 검증.
3. **[★★☆ 폭 margin · Low]** ★★☆(60~75, 15%p)이 ★☆☆(50~60, 10%p)보다 넓은 근거 명시.
4. **[OI 등록 확인 · Low]** 변경이력 138행 "open-issues.md 정합 점검(범위 외)" — 하한 보정(70→50%)이 OI-9에 실제 등록됐는지 Applier가 확인(QA-08~10은 "open-issues 등록 대상"으로 명시, QA-13만 "범위 외"로 미등록 의심).
5. DP 역검토: DP-0001 비용 기준 라우팅·DP-0004 scale-to-zero·DP-0005 캐시(OI-7).
