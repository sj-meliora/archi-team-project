# Review: QA-12 Maintainability — 모듈 교체 용이성

> source: context/qa/QA-12-maintainability.md + QAS-12-maintainability.md
> verdict: **Sound ◎ / KPI ○** — CIS p95 재배치 불요(건강) + 경계 정의 조건은 정확. 잔여는 ★ 급간이 정수 3값(1/2/3)이라 변별 입도가 거칠고 main 축(CIS)이 컴포넌트 경계 정의에 전적 종속 · severity **Low**
> lenses: (1) Agentic Workflow 전문가 · (2) 20년차 수석 아키텍트 · (3) 대규모 Workflow Runner 인프라 아키텍트
> 특별 초점(round-04): ★ 등급 척도(CIS p95 1/2/3 역방향 + 경계 정의 조건) 검증 무게중심.

## 원문 요약
- 정의: 컴포넌트·prompt/tool-def·LLM 모델 교체 내성 + model-agnostic 무중단. 지배적 비용 = prompt/tool/모델 교체.
- 헤드라인: `CIS p95 ≤3개 + 컴포넌트 경계 정의 선결`.
- ★ 급간: main = CIS p95(역방향, 낮을수록 상). ★★★ ≤1 / ★★☆ =2 / ★☆☆ =3 / 불합격 ≥4 또는 경계 미정. 조건: 컴포넌트 경계 정의 고정. 보조 게이트: 모델 교체 무중단.

## 렌즈 1 — Agentic Workflow 전문가 관점 (필드 근거 보강/반박)
"agentic 유지보수의 진짜 비용 = prompt/tool-def·모델 교체·온보딩"(컴포넌트 자체가 아니라)을 정확히 짚었다. 모델 마이그레이션 비용(2 eng × 2주 ≈ $16k, [VentureBeat])을 근거로 무중단·온보딩 ≤1일을 보조 게이트로 보존한 것도 적절. 그러나 red-team 반박: **★ main 축은 CIS(컴포넌트 영향 범위)인데, 정의가 말한 "지배적 비용"은 prompt/모델 교체**다 — 즉 **별점을 매기는 축(CIS)과 정의가 강조한 비용 축(prompt/모델)이 어긋난다.** CIS는 전통 SW 결합도 지표이고, agentic 지배 비용(prompt 깨짐·모델 교체)은 보조 게이트로 밀렸다. → 권고 1(agentic 축을 별점에).

## 렌즈 2 — 20년차 수석 아키텍트 관점 (★ 급간 검증 핵심)
- **규칙 적용**: CIS를 main, 경계 정의를 조건, 무중단을 보조 게이트로. 정확. ○.
- **급간 reasonableness + 거친 입도(가장 날카로움)**: CIS p95가 **정수**(1/2/3)라 ★★★=1 / ★★☆=2 / ★☆☆=3으로 **각 등급이 단일 정수값**. 이건 gradable이긴 하나 **변별 입도가 매우 거칠다** — p95가 1.5나 2.7 같은 분수일 수 있는데(p95는 분포 백분위라 보간되면 비정수) 표는 정수만 상정. p95=2.4면 ★★☆인가? 또 설계 대안 둘이 모두 p95=2면 ★ 동률이라 ATAM 변별 불가. → 권고 2.
- **하한 보정 정합(OI-9)**: §측정(39행 ≤3 유지), 등급표, 변경이력(재배치 불요), counsel(불요), QAS-12(`p95 ≤3개`) **일치**. 재배치 안 함(p95≤3 현실적). glossary 없음. **OI-9 통과.**
- **변별력**: 하한 p95≤3이 "잘 분리된 모듈 ripple 상단"이라 비현실 아님 → 사문화 없음. 단 정수 입도가 변별 약점.
- **main 축 종속성**: CIS는 "컴포넌트를 어떻게 세느냐"에 민감 → 경계 정의를 조건으로 못박은 건 정확하나, **★ 급간 자체가 경계 정의 선택의 함수**라 경계를 굵게 잡으면 CIS↓(★↑), 잘게 잡으면 CIS↑(★↓). 경계 정의가 ★를 좌우 → silent cap.

## 렌즈 3 — 대규모 Workflow Runner 인프라 아키텍트 관점
CIS = 변경 시나리오(노드 교체·SDK 플래그·모델 v→v+1·온보딩) 세트의 영향 컴포넌트 집계. workflow-as-code(activity 교체·큐/계약 분리)·버저닝(in-flight 구/신버전 공존)·blue-green이 CIS를 낮추는 메커니즘 → ★ 급간이 이 분리 설계를 보상. mock 결합도가 실시스템보다 낮으면 CIS 낙관 편향(이미 노트). runner KPI: `변경 시나리오별 CIS 분포(p95/max) + 경계 정의 sensitivity(경계 굵기 ±1 시 CIS 변동)` — 경계 종속성 노출.

## Stage 2 권고
1. **[agentic 축 별점화 검토 · Low]** 정의가 강조한 지배 비용(prompt/tool 수정 ≤2·모델 교체)이 보조 게이트로 밀림 — `검토: prompt/tool-def 수정 수를 보조 별점 축으로 병기(CIS와 이중 축)`.
2. **[정수 입도 · Low]** CIS p95가 정수 1/2/3이라 변별 거침 + 보간 p95(비정수) 미상정 — `제안: ★★☆ "1<p95≤2", ★☆☆ "2<p95≤3"으로 구간화해 분수 p95 수용 + 동률 변별 보강`.
3. **[경계 정의 종속 silent cap · Low]** ★ 급간이 컴포넌트 경계 굵기 선택의 함수임을 명시(경계를 굵게 잡으면 CIS↓·★↑).
4. DP 역검토: DP-0004/0005의 버저닝·계약 분리·blue-green tactic + FR-0003 영향범위 자동분석의 CIS 데이터 공급(OI-7).
