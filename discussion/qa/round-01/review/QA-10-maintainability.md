# Review: QA-10 Maintainability — 모듈 교체 용이성

> source: `context/qa/QA-10-maintainability.md` + `QAS-10-maintainability.md`
> verdict: **Sound ○ / KPI ○** — 건강한 QA. 단 평균이 tail을 은닉하고 agentic 유지보수축이 빠짐 · severity **Low**
> lenses: (1) Agentic Workflow 전문가 · (2) 20년차 수석 아키텍트 · (3) 대규모 Workflow Runner 인프라 아키텍트

## 원문 요약
- **정의**: 구성요소 변경 시 타 요소 영향 최소화.
- **KPI**: 평균 Change Impact Scope ≤ 2개 컴포넌트
- **QAS**: 자극=한 구성요소 변경/교체 / 응답=타 요소 영향 최소화 / 설계연결=DP-0004, FR-0003.

## 렌즈 1 — Agentic Workflow 전문가 관점

**Agentic 시스템 유지보수의 지배적 비용은 컴포넌트가 아니라 prompt/tool-def/eval이다.** 현재의 “컴포넌트” 관점은 이 핵심 축을 놓친다:
- **툴체인 변경 전파**: SDK 컴파일러 플래그·IR 포맷이 바뀌면 agent의 prompt·tool 정의를 얼마나 고쳐야 하나? 이게 실제 운영의 가장 잦은 변경이다.
- **모델 교체 내성(model-agnostic)**: LLM 버전 업그레이드가 워크플로우를 깨면 안 된다. 모델 교체 시 무중단·재검증 비용이 유지보수 핵심 지표.
- **eval 유지보수**: QA-03/09의 검증 하네스도 변경에 따라 갱신돼야 한다.
- overview의 **140+ 모델** 맥락 → **신규 모델 온보딩 시간**도 유지보수의 1급 지표.

## 렌즈 2 — 20년차 수석 아키텍트 관점 (QA 완성도)

- **건강한 QA**: 모듈성(낮은 결합)이라는 단일 관심사가 명확하고 CIS는 측정 가능. 이 세트에서 KPI 상태가 양호한 편.
- **평균의 함정**: `평균 CIS ≤ 2`는 tail 위험을 숨긴다(한 변경이 12개를 건드려도 평균에 묻힘). **p95 또는 max**가 적절.
- **세분성 의존**: “컴포넌트”를 어떻게 세느냐에 따라 값이 흔들린다 — 컴포넌트 경계 정의를 동반해야 비교 가능.
- 확장: 변경 유형별(파이프라인 단계 추가, 툴 버전 교체) 소요 시간 지표를 추가하면 모듈성을 다면 측정.

## 렌즈 3 — 대규모 Workflow Runner 인프라 아키텍트 관점

**workflow-as-code 관점에서 “모듈 교체”는 activity 교체로 환원된다.**
- **큐 인터페이스 결합도**: 노드 간 통신을 큐/계약(스키마)으로 분리하면 한 노드 구현 교체가 인접 노드를 건드리지 않는다 → CIS≤2를 구조적으로 보장. 새 파이프라인 단계 추가 = activity·DAG 항목 추가로 국소화.
- **무중단 배포·버전 스큐**: worker blue-green, 워크플로우 버저닝(in-flight는 구버전, 신규는 신버전)으로 배포가 운영을 깨지 않게. LLM 모델 교체도 activity 내부 버전 교체로 흡수(model-agnostic, 렌즈1).
- **runner 측 KPI**: 워크플로우 버저닝 지원 여부, 노드 추가 소요(파일/계약 수), 무중단 배포 성공률.

## 판정

| 항목 | 판정 | 근거 |
|---|---|---|
| QA 자체가 sound한가 | ○ | 모듈성/교체 용이성은 명확한 단일 관심사 |
| KPI가 측정 가능한가 | ○ | CIS는 측정 가능(컴포넌트 정의만 보완) |
| KPI가 현실적/적절한가 | ○ | 합리적. 평균→tail 전환 및 agentic 축 추가 권장 |
| 정의↔KPI↔QAS 일치 | ○ | 일관 |

## Stage 2 권고

- **KPI 보강**:
  - `평균 CIS ≤ 2` → **`CIS p95 ≤ ◯`**(tail 관리) + 컴포넌트 경계 정의 명시
  - 추가: **`SDK 툴체인 변경 시 prompt/tool-def 수정 ≤ ◯`**, **`LLM 모델 교체가 워크플로우 무중단(model-agnostic)`**, **신규 모델 온보딩 시간 ≤ ◯**
- **연계**: FR-0003(영향 범위 자동 분석)이 CIS 측정 데이터를 제공하는지 역검토.
- DP 연결 점검: DP-0004(단순 인프라)·DP-0005가 prompt/모델 교체 내성을 다루는지 역검토.
