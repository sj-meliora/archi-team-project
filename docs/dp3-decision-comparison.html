축① 결선 — gVisor vs microVM 기준별 판정

별점은 "격리 계층이 해당 QA에 끼치는 영향" 기준의 예시 캘리브레이션 — Q2′ 마이크로벤치로 확정.

gVisor비교안 (결선 상대) microVM선정안 판정
Performance-E2E
(QA-10)		 ★☆☆20GB×2/단계가 netstack(네트워크)+gofer(파일) 이중 가로채기 — A5 전달세금 증폭 ★★★virtio-net/blk near-native microVM 결정적
Availability
(QA-02)		 ★★☆호환성 구멍 = 단계 실행 중 실패 리스크 ★★★자기 커널 — Lambda 규모 실증 microVM 약우위
Controllability
(QA-03)		 ★★★중단·게이트는 제어평면(DP-01/0003) 소관 — 비변별. 단 C-03 봉쇄 논증은 공유 커널이라 부담↑ ★★★하드웨어 벽 — 봉쇄 논증 단순 microVM 약우위
Scalability
(QA-01)		 ★★☆netstack CPU 세금이 storage-bw knee를 앞당김 ★★★오버헤드 ~5MB — 밀도 영향 미미 microVM 약우위
Correctness
(QA-07)		 ★★☆toolchain syscall 미지원 구멍 가능 ★★★완전한 커널 — 무수정 구동 microVM 우위
C-01 · 인프라 어디서나 구동 (유일 강점이었음) Kata RuntimeClass + bare-metal 가용 동률 (강점 소거)
소거 논리 — gVisor가 이기는 시나리오는 둘뿐이었다: ① 가상화 불가 환경 → bare-metal 가용 입력으로 소거 · ② I/O 가벼운 워크로드 → dp2 = A5 확정으로 워크로드가 정반대(단계마다 20GB 왕복)가 되어 소거. → 방향은 microVM으로 확정, Q2′ 벤치는 "선택 근거"가 아니라 budget 통과 확인용.

축② 승인 배치 — 3안 비교 기준선 2 + 채택 1

전면 HITL 기준선 · 격추

  • QA-01: 사람 = USL α항, workload에 비례 — 일 ~50건 승인
  • QA-03: 승인 피로 → rubber-stamping으로 게이트 실질 무력화
  • QA-02: 사람 부재 = 파이프라인 블로킹
  • 시스템 전제("사람 개입 없이")와 모순

3단 위험 티어 배정 채택

  • 원리: 승인 경계 = 격리 경계 — 효과가 컨테이너 폐기를 넘어 지속되는가(기계 판정 술어)
  • QA-01: 에스컬레이션 ∝ 산출물 수 — 사람 병목 분리
  • C-03: 고위험 HITL 100% 게이트 충족
자동샌드박스 내부 — 노드 실행·중간 처리 (롤백 = 컨테이너 폐기)
정책 사전승인스토리지 write(스코프 자격증명+서명) · canary 배포 · 허용 외부 API
액션별 HITLproduction 승격 · credential 사용 · delete

전면 자동 승인 부적격

  • C-03 위반: "고위험 액션 HITL 통과율 100% · 우회 0건"은 pass/fail 제약 — 비교 매트릭스에 올라올 자격 없음
  • 격리 등급이 아무리 강해도 인가된 나쁜 배포는 샌드박스가 못 막는다

TP-1 — 왜 이 조합만 성립하는가 벽 강도 × 자동존 폭

벽 강도 → (아래: 약 · 위: 강)

✗ 강한 벽 + 전면 HITL

격리 비용은 내고 처리량은 못 얻음 — QA-01 사람 병목 + rubber-stamping.

✓ 강한 벽 + 넓은 자동존

채택 (microVM + 3단 배정) — 가장 강한 벽이 가장 넓은 자동존을 떠받쳐 ASR#1(Scalability)의 "사람 개입 없는" 처리량을 만든다.

— 약한 벽 + 좁은 자동존

로컬 Claude Code 모델 — 사람이 곧 샌드박스. 안전하나 확장 불가(기준선).

✗ 약한 벽 + 넓은 자동존

C-03 봉쇄 논증 실패 — injection 잔여 ~30%의 임의 코드가 커널 공유 경계 안에서 자유.

자동존 폭 → (왼쪽: 좁음/HITL · 오른쪽: 넓음/자동)
